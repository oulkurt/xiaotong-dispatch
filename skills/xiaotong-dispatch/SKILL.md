# 小瞳派单

小瞳 Work 是用户电脑上的桌面 Agent，下文简称「小瞳」。小瞳有自己的项目、记忆、模型和工具。
本 Skill 让你把任务交给小瞳。你负责选项目、派单、等待和汇报，小瞳负责做事。

## 何时使用

- 用户要小瞳做事：「让小瞳帮我整理这周的周报」「小瞳，帮我查一下这个报错」「小瞳来写个测试」「把这个交给小瞳」。
- 用户追问已派出的任务：「小瞳好了吗」「让小瞳接着改」「让小瞳停下」「在小瞳里打开」。

## 何时不用

- 用户在讨论或开发小瞳 Work 软件本身。
- 用户只提到小瞳，没有要它做事。拿不准时，先问：「要我把这件事交给小瞳去做吗？」

## 规矩

1. 任务交给小瞳后，你不再自己做同一件事。
2. 小瞳看不到当前对话。派单时，把小瞳需要的上下文写进任务正文。
3. 不把密钥、令牌和密码写进任务正文。
4. 只转述小瞳的结果。不补写小瞳没有说的内容。

## 工具

优先用 MCP 工具。工具名以 `xiaotong_` 开头：

| 工具 | 用途 |
|---|---|
| `xiaotong_list_projects` | 列出项目，并按当前目录推荐项目 |
| `xiaotong_dispatch_task` | 派单，返回任务号（`sessionId`） |
| `xiaotong_wait_task` | 等待结果，每次最多 45 秒 |
| `xiaotong_list_tasks` | 列出最近派出的任务 |
| `xiaotong_stop_task` | 停止任务 |
| `xiaotong_open_task` | 在小瞳 Work 窗口打开任务 |

没有这些工具时，改用命令行 `proma`，用法见 [references/cli.md](references/cli.md)。
两者都不可用时，告诉用户：「当前环境连不到你电脑上的小瞳 Work。」然后按「出错时」一节给出处理办法。

## 流程

### 1. 整理任务正文

- 去掉称呼和触发词，保留用户的原意。不改写用户的要求。
- 补上小瞳缺少的上下文：相关文件的绝对路径、前文的结论、用户给的限制条件。
- 有文件要一起交给小瞳时，把绝对路径放进 `files`。

### 2. 选项目

调用 `xiaotong_list_projects`，传入当前工作目录。然后按顺序判断：

1. 用户点名了项目，且只匹配到一个：直接用这个项目。
2. 点名匹配到多个项目：列出这几个，请用户选。
3. 返回结果里有推荐项目：问一句「在小瞳的『{项目名}』里办，可以吗？」
4. 以上都不满足：按最近使用的顺序列出项目，每页 8 个，请用户回复序号或名称。

列表这样写。序号跨页连续，第 2 页从 9 开始：

```text
要在小瞳的哪个项目里办？（第 1/2 页）
1. 周报整理
2. xiaotong_work（~/Downloads/02-Projects/xiaotong_work）
…
回复序号或项目名；回复「更多」看下一页。
也可以先在小瞳 Work 里新建项目，再告诉我项目名。
```

只有一页时，不写页码，也不提示「更多」。

用户回答以后再派单。

### 3. 派单

调用 `xiaotong_dispatch_task`，传入：

- `projectId`：第 2 步选定的项目。
- `prompt`：第 1 步整理好的任务正文。
- `caller`：你的产品名，例如 Codex、Claude Code、Trae、WorkBuddy。
- `sessionId`：只在续做同一个任务时传入，填原来的任务号。
- `files`：可选，要交给小瞳的文件的绝对路径。

派单成功后，告诉用户：「已交给小瞳，在『{项目名}』里开工了。」

### 4. 等待

反复调用 `xiaotong_wait_task`，每次最多等 45 秒，累计约 8 分钟。

- 返回 `completed`：进入第 5 步。
- 返回 `failed`：把错误原因告诉用户。
- 返回 `stopped`：告诉用户任务已停止。
- 累计约 8 分钟后仍是 `running`：停止等待，按「转后台」汇报。

### 5. 汇报

做完时：

```text
小瞳在『{项目名}』里做完了：
{小瞳回复的要点：结论、产出文件的路径、需要用户处理的事}
想看完整过程，可以说「在小瞳里打开」。
```

小瞳的回复较短时，原样转述。回复很长时，先给要点，再说明完整内容在小瞳 Work 里。

转后台时：

```text
小瞳还在『{项目名}』里做这件事。你可以在小瞳 Work 窗口看进度，稍后问我「小瞳好了吗」。
```

### 6. 后续指令

- 「小瞳好了吗」：用上次的任务号调用 `xiaotong_wait_task`，`waitMs` 设为 0，立即查状态。还在运行时，按第 4 步继续等。
- 不记得任务号：调用 `xiaotong_list_tasks`，按任务正文和时间找到对应任务，再向用户确认。
- 「让小瞳接着…」：把新要求作为任务正文，带上原来的任务号派单。
- 「让小瞳停下」：调用 `xiaotong_stop_task`。
- 「在小瞳里打开」：调用 `xiaotong_open_task`。

## 出错时

| 情况 | 处理 |
|---|---|
| 你运行在云端模式或网页版 | 云端环境连不到用户的电脑。请用户切换到桌面端的本地模式，再试一次。 |
| 小瞳 Work 没有运行 | 工具会自动启动小瞳 Work，最多等 30 秒。仍然失败时，请用户手动打开小瞳 Work。 |
| 提示未选择 Agent 渠道 | 请用户在小瞳 Work 设置里选择 Agent 渠道。 |
| 提示外部调度已关闭 | 请用户在小瞳 Work 设置里打开「允许外部 Agent 调度」。 |
| 命令连接本机被拒绝 | 你的命令沙箱拦截了本机连接。改用 MCP 工具；没有 MCP 工具时，请用户放行 `proma` 命令，或按小瞳派单的安装说明配置 MCP。 |
| 任务号对应的会话正在运行 | 等它做完再续做；或者不带任务号，新开一个任务。 |
| 找不到 `proma` | 请用户安装或升级小瞳 Work，并打开一次。 |
